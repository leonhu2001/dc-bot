# 手機版 V8 共用介面及客服審核通知：驗收基準

## 範圍

- 顧客官網、下單、陪玩、VIP、會員、訂單、錢包、遊戲資訊頁
- 員工後台、接單大廳、報單、薪資、內部轉帳、綁店管理頁
- 客服工作台、訂單、客戶、財務、付款/儲值、報單審核頁
- 客服審核通知：付款（含雞腿）、內部轉帳、儲值、VIP 保級、陪玩報單

本版以原功能/權限/資料處理程式為底；改由手機版 V8 **最後載入**的共同樣式與互動層統一介面。舊行動版 CSS 不再負責最終幾何尺寸，但作為可逆相容底層保留，桌面版不載入 V8。

## 統一準則

| 項目 | 準則 |
| --- | --- |
| 手機設計寬度 | 320–767px，單一內容 rail，最大 560px |
| 內容左右留白 | 12–18px，依螢幕寬度連續變化 |
| 頂部標題欄 | 62px + 上方安全區 |
| 底部導覽 | 72px + 下方安全區 |
| 卡片 | 18px 圓角，統一線框與間距 |
| 操作控制 | 最小 46px 高、文字至少 16px，防 iOS 自動放大 |
| 長資料 | 內容換行，寬表格在表格內捲動，不讓整頁水平溢出 |
| 螢幕鍵盤 | 聚焦輸入時暫時收起底部導覽，避免覆蓋輸入框 |
| 返回上一層 | 使用穩定的同站 URL；不依賴只能透過歷史返回 |
| 無障礙 | 鍵盤略過導覽、清楚的焦點框、目前頁 aria-current、表單錯誤定位 |
| 動畫 | 尊重 reduced-motion |
| 換頁 | 顯示短暫進度提示，回上一頁不會長期卡住提交狀態 |

## 客服通知的統一資訊階層

1. **客服審核｜案件類別｜目前狀態**
2. 一句話說明客服需要執行的動作（已結案則說明處理結果）
3. **案件編號 → 申請人／老闆 → 金額**（該案件沒有的欄位不顯示）
4. 各流程原有的重要資料：付款方式/票口、轉出/轉入、儲值來源、VIP 名單、報單單別/填報人
5. **前往審核**：一律是安全的 HTTPS「連結」按鈕，不在 Discord 直接核准
6. 統一頁尾、待審核琥珀色／通過綠色／駁回紅色／取消灰色／異常橘色

原本的客服身分組 mention/不 mention 規則、訊息 ID、原通知狀態更新、原網站審核權限、重試去重規則均保持。報單通知仍發至原指定頻道，絕不把報單誤發到付款審核頻道。

## 自動驗證

- 靜態契約：三套 shell 都載入同一個 V8 CSS/JS、桌面版隔離、共用設計尺寸
- Playwright：手機寬 320/375/390/430，每個尺寸跨首頁、下單、VIP、服務規範頁驗證頁面沒有水平溢出且導覽寬度不跳動；744px 另驗證相同版心
- Playwright：底部導覽切換、目前頁標記、返回上一層
- 單元測試：所有審核卡標題/顏色/欄位順序/連結、報單通知 nonce 與角色 mention 安全限制
- 原 GitHub CI 的 Python 回歸測試及 browser smoke

## 上線後實際票口/權限驗收

以下只能在正式身分登入的手機與 Discord 測試帳號實測，CI 不能假裝完成：

- Android Chrome、iPhone Safari，含瀏海/底部手勢列及系統字體放大
- 顧客：下單分類 → 選人/數量 → 查看報價 → 付款；查看訂單、VIP 及錢包
- 員工：接單大廳 → 工作者詳情 → 報單填寫 → 查詢薪資/內部轉帳
- 客服：訂單工作區 → 客戶資料 → 付款/儲值審核 → 拒絕時原因/二次確認
- Discord：五類審核通知，包含已核准／已駁回的舊訊息更新、正確導向網站、無重複發送
- 檢查現有價格、折扣、分潤、已結單報單、VIP 計時等不受影響

## 安全回退原則

本版不修改 SQL schema、訂單定價、薪資、會員點數或審核權限。整套手機 V8 介面只要移除兩份共用 layout 的 V8 CSS/JS 引用，即可回到原來外觀；業務程式及資料仍在。服務更動須先 GitHub CI 全綠，依原有安全部署工具上線並確認 Bot/Web/Nginx 狀態。
